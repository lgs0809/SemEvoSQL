# B.8：目录读取职责重构与旧入口遗漏修复

本批是 B.8 的查询读取边界收敛，不代表 B.8、SemEvoSQL 或两个项目全部完成。仓库已沿用用户移动后的 `实习/代码/QueryWeaver`，没有重建旧路径或覆盖工作区。

## 问题与结果

此前按模型读取、目录详情和候选组装各自做 hash 检查，执行读取还放在全目录缓存类里。旧 Blueprint 入口缺少模型 ID 时会回退全目录；候选入口按物理表解析时，两个请求表中只找到一个也会继续执行。

新增 `SemanticCatalogReadService` 统一一次逻辑读取的前后权威 hash 校验、完整模型身份校验、24 模型预算和物理表的完整／唯一解析。候选扩展、资产所属模型定位、摘要分页均包在同一次校验内。通过 Spring 构造器注入复用该服务，数据读取仍使用既有 MyBatis；完整目录的缓存仍使用既有 Caffeine，没有另造缓存或锁。

规划、运行时目录提示、语义一致性检查、SQL 编译／执行、跨源执行和成功案例资产指纹都改用此服务。成功案例指纹读取还必须匹配该请求已冻结的 hash。全目录 `SemanticCatalogCache` 移除了查询子集职责。
