## 实现

- 普通请求先执行 `QueryEnhanceNode`，再进入确认检测和 `RequestAnalysisNode`。新增请求补全契约有 READY／NEEDS_CONTEXT 两条分支，非法 JSON、状态与正文冲突、不存在的上下文序号均阻止后续执行。
- `ORIGINAL_REQUEST` 保留用户原文；`rootCanonicalQuery` 保留首次完整改写；`ACTIVE_QUERY` 随当前 Todo 切换。分析实际收到的问题单独落 Run 事件。上下文快照随原生检查点保存，事件保留线程、引用轮次、快照摘要和已应用确认 revision。
- 上下文确认复用现有 HITL 与原生中断／恢复，`CONTEXT_REFERENCE` 不允许保存个人或项目语义绑定。内部 SQL 生成、已批准计划恢复和执行回退保持原有路径，不重新拆任务。
- 修复默认 SQL 2 次、语义／执行重规划共用 2 次、补检索 2 次、追加问询 2 次；移除额外总次数门槛。Todo 切换保留整个 Run 已消耗的修复额度。
- 所有运行时问询在持有 Run 行锁时检查同一张持久化问询表：首次正常问题免费，之后最多两轮。并发创建复用同一个待答问题；原生等待状态携带实际累计额度。
- 必要后置语义复核不再受“一次”上限限制；复核失败／输出非法不退回确定性 PASS。被语义否决后的新版本强制复核，effect 输入保留 SQL、计划、结果及复核要求，避免复用旧版本通过记录。
